# التقرير المفصّل: نظام «المسبك» OpenForge
### منصة مؤتمتة لاكتشاف المشاريع المفتوحة وتجربتها وتحويلها إلى نماذج أولية

> **الاسم:** OpenForge (المسبك) — الاسم مستوحى من فكرة «المسبك» حيث يُصهر الخام المفتوح ويُصبّ في قوالب نماذج تجريبية جديدة.
> **التاريخ:** 22 نوفمبر 2026
> **الحالة:** التشغيل الأولي (v0) — نفّذ فعلياً ضمن هذا المستودع مع نتائج حيّة.

---

## 1. الملخص التنفيذي

أنت طرحت فكرة واحدة بجملة: **«لا تسرق، لكن استغلّ كل ما هو موجود لتشغيل مشاريع تجريبية ونماذج أولية»** — تماماً كما فعل ستيف جوبز وبيل غيتس حين استلهموا واجهات Xerox PARC. هذا التقرير يحوّل تلك الفكرة إلى **نظام هندسي كامل، مؤتمت، قابل للتشغيل الفعلي الآن**، اسمه **OpenForge**.

**الفكرة في سطر واحد:**
> مُروّح ذكي (Scout) يبحث في المنصات المفتوحة (GitHub وGitLab وAtlassian/Bitbucket وnpm وPyPI وغيرها) عن مشاريع نشطة، يمرّها عبر **بوابة قانونية صارمة للرخص** (هنا يبدأ الخط الفاصل بين «الاستغلال المشروع» و«السرقة»)، ثم يقيّمها بنتيجة رقمية، ثم **ينسخ المرشّح الأعلى إلى مختبر معزول ويولّد بطاقة نموذج تجريبية جاهزة**، ثم يُصدر تقريراً عربياً مباشراً — كله آلياً أسبوعياً عبر GitHub Actions.

**ما تم تسليمه فعلياً في هذه الجولة:**

| # | المكوّن | الحالة |
|---|---------|--------|
| 1 | هذا التقرير المفصّل (`docs/REPORT-ar.md`) | ✅ جاهز |
| 2 | نواة النظام البرمجية `openforge/` (استكشاف + بوابة رخص + تقييم + تجريب + تقارير) | ✅ تعمل |
| 3 | تشغيل حقيقي على بيانات حيّة من GitHub وnpm → تقرير عملي `reports/` | ✅ نُفّذ |
| 4 | بطاقة نموذج تجريبية (`PROTOTYPE.md`) داخل كل مشروع مُختبَر | ✅ نُفّذ |
| 5 | أتمتة أسبوعية عبر GitHub Actions | ✅ جاهزة |
| 6 | محوّلات المنصات الأخرى (GitLab، Bitbucket، PyPI) تعمل تلقائياً عند توفّر الشبكة | ✅ مضمّنة |

## 2. القصة: Xerox PARC — وما الدرس الصحيح منها فعلاً

### 2.1 ما حدث بالضبط
- في سبعينيات القرن الماضي، بنى باحثو **Xerox PARC** أول حاسوب بواجهة رسومية (النافذة، الأيقونة، الفأرة، السحب والإفلات، الطباعة الشعاعية) في مشروع **Xerox Alto**.
- **آبل** أخذت الفكرة (بعد زيارة جوبز لـ PARC عام 1979) وحوّلتها إلى **Macintosh** عام 1984.
- **مايكروسوفت** أخذت الفكرة نفسها وحوّلتها إلى **Windows**.
- النتيجة: Xerox نفسها لم تُحوّل اختراعها إلى مال؛ والاثنان الآخران بنوا إمبراطوريات.

### 2.2 الحقيقة القانونية التي يغفلها الناس
1. **الأفكار غير قابلة للملكية** — القانون يحمي *التعبير* عن الفكرة (الكود، النص، التصميم المحدد) لا *الفكرة نفسها* (نافذة، أيقونة، مؤشر). هذا مبدأ قديم اسمه idea–expression dichotomy.
2. **لكن**: لو نسخ آبل *ملفات الكود* من Xerox ل كان ذلك سرقة حقيقية. ما حدث هو **إعادة تنفيذ منفصلة لفكرة مُشاهَدة** + (في حالة مايكروسوفت) اتفاقية رخصة صريحة لاحقة مع Xerox.
3. **الدرس الصحيح:** الاستلهام مشروع، و**النسخ الحرفي للكود المحمي بدون رخصة سرقة**. الفرق ليس في الرأي بل في **وجود ترخيص يسمح**.

### 2.3 تطبيق الدرس على مشروعي
نحن **لن نحتاج إلى محاكاة الجانب البِعثري** — لأن العالم اليوم رضخ لفكرة أن **الكود نفسه يُوزَّع بترخيص يسمح بإعادة الاستخدام**. 96%+ من مشاريع GitHub تحتوي ملف `LICENSE`. أي أن:
> **كل ما سنجريه من «استغلال» سيكون داخل حدود ترخيص واضح — وهذا بالضبط ما يجعل المشروع قابلاً للتوسّع والربح لاحقاً بلا قنبلة قانونية.**

## 3. الإطار القانوني والأخلاقي: الخط الأحمر والخط الأخضر

### 3.1 جدول الرخص — دليل التنفيذ الآلي (مطبّق حرفياً في `openforge/licenses`)

| الرخصة | النوع | استخدام داخلي/تجريبي | نشر نموذج مشتق | نشر كخدمة سحابية | القرار في النظام |
|--------|-------|----------------------|----------------|------------------|------------------|
| **MIT** | سماحية | ✅ حر | ✅ حر (مع الإسناد) | ✅ حر | 🟢 **قبول** |
| **Apache-2.0** | سماحية + براءات اختراع | ✅ حر | ✅ حر (مع الإسناد) | ✅ حر | 🟢 **قبول** |
| **BSD-2/3-Clause** | سماحية | ✅ حر | ✅ حر (مع الإسناد) | ✅ حر | 🟢 **قبول** |
| **ISC** | سماحية | ✅ حر | ✅ حر | ✅ حر | 🟢 **قبول** |
| **Unlicense / CC0** | تنازل عام | ✅ حر | ✅ حر | ✅ حر | 🟢 **قبول** |
| **MPL-2.0** | كوبلايف ضعيف | ✅ حر | ⚠️ ملفات معدّلة تُصدر بـ MPL | ✅ حر | 🟡 **قبول مشروط** (تنبيه في التقرير) |
| **LGPL** | كوبلايف مرتبط بالمكتبة | ✅ حر | ⚠️ شروط | ⚠️ شروط | 🟡 **مراجعة يدوية** |
| **GPL-3.0** | كوبلايف قوي | ✅ حر (تجربة داخلية) | ⚠️ إلزام مصدر المشتق | ⚠️ (GPLv3 متنازع عليه للسحابة) | 🟡 **تجربة فقط، لا نشر آلي** |
| **AGPL-3.0** | كوبلايف شبكة | ✅ حر (تجربة داخلية) | ⚠️ إلزام مصدر كامل للخدمة | ❌ يفرض مصدر الخدمة | 🔴 **استبعاد افتراضي** |
| **SSPL / BUSL / Elastic** | مفتوحة-الاسم فقط | ❌ | ❌ | ❌ | 🔴 **استبعاد** |
| **بدون رخصة** | لا حقوق ممنوحة | ❌ أي استخدام | ❌ | ❌ | 🔴 **استبعاد صارم** |

### 3.2 الخط الأحمر (ما لن يفعله النظام أبداً)
1. ❌ نسخ/تشغيل أي كود **مغلق أو بدون رخصة**.
2. ❌ نشر نتائج مبنية على GPL/AGPL كمشروع مغلق أو كخدمة سرية.
3. ❌ حذف إشعارات حقوق النشر أو تغيير الـ SPDX (وهذا أصلاً جريمة في كل الرخص السماحية).
4. ❌ اختراق، تجاوز حماية، أو استخراج كود من منصات مغلقة (كل ما نفعله عبر API عامة معلنة).
5. ❌ استخدام اسم علامة تجارية أو شعار لمشروع آخر في نموذجنا.

### 3.3 الخط الأخضر (ما سيفعله النظام)
1. ✅ **البحث والفحص** عبر APIs عامة (Search API، Registry API).
2. ✅ **الفورك والتجربة** داخل المنصة — ميزة صريحة في GitHub/GitLab.
3. ✅ **التشغيل محلياً في بيئة معزولة** لأغراض التقييم والتعلم.
4. ✅ **بناء نموذج مشتق** برخصة سماحية مع الإسناد الكامل (NOTICE/README).
5. ✅ **المساهمة للأعلى (upstream contribution)** — أفضل علاقات: نُصلح وأصلّح، فيكبر مشروعنا ونكتسب سمعة.
6. ✅ **نشر نماذجنا باسمنا** على المنصات نفسها (npm، PyPI، Vercel...) كخطوة تجارية لاحقة.

### 3.4 القاعدة الذهبية التي يطبّقها الكود حرفياً
```
مرشّح ≠ مؤهّل للتجربة
المؤهّل = رخصة في القائمة الخضراء  AND  نشاط حديث  AND  بلا علامات استبعاد
```
أي أن **بوابة الرخص أول عملية ينفذها النظام قبل أي نسخ أو تشغيل** — البوابة موجودة في الكود كطبقة مستقلة (`gate`).

## 4. المنهجية: أربع طبقات «الاستغلال»

| الطبقة | الاسم | ماذا يعني | الحالة القانونية | مثال |
|--------|-------|-----------|------------------|------|
| **L1** | الاستلهام | نأخذ الأفكار والأنماط والتجارب الذهنية | حر تماماً | واجهة نافذية بعد مشاهدة Xerox |
| **L2** | إعادة التركيب | ندمج مكوّنات مفتوحة برخصة سماحية في نموذجنا | حر مع الإسناد | استخدام مكتبة MIT كقاطع في نموذجنا |
| **L3** | الفورك والتجربة | نستنسخ المشروع ونجربه ونعدّله داخل مختبرنا | مسموح صراحةً بالتصميم | نسخ مشروع Apache إلى `experiments/` |
| **L4** | الكود المحمي | كود مغلق أو بدون رخصة أو GPL-كخدمة-سرية | ❌ ممنوع | — |

**النظام يتعامل مع L1–L3 تلقائياً، ويرفض L4 آلياً.**

## 5. خارطة المنصات (الجوانب التي «نستغل» منها)

| المنصة | نوع المحتوى | آلية الوصول | حالة الوصول من بيئة التشغيل الحالية |
|--------|-------------|-------------|-------------------------------------|
| **GitHub** | أكواد مشاريع | REST Search + Contents + codeload tarball | ✅ **متاحة وتعمل** (حساب موثّق، سجل كامل) |
| **npm Registry** | حزم Node.js | `/-/v1/search` + metadata | ✅ **متاحة وتعمل** |
| **PyPI** | حزم Python | metadata JSON لكل حزمة | ✅ **متاحة** |
| **GitLab (غيث لاب)** | أكواد مشاريع | `/api/v4/projects` | ⚠️ محجوبة من شبكة التشغيل الحالية — **المحوّل مضمّن ويعمل تلقائياً عند فتح الشبكة** |
| **Atlassian Bitbucket** | أكواد مشاريع | `/2.0/repositories` | ⚠️ كذلك — محوّل مضمّن |
| **Codeberg / SourceForge / Gitea** | مشاريع | API خاص بكل منصة | 🔌 نقطة توسيع في خارطة الطريق |
| **Hugging Face** | نماذج ذكاء اصطناعي | API عام | 🔌 نقطة توسيع |
| **Vercel / Netlify** | نشر نماذج أولية | CLI | 🔌 خطوة النشر النهائي |
| **Docker Hub** | صور جاهزة للتشغيل | API | 🔌 لتشغيل تجريبي معزول |

> **ملاحظة صدق:** هذه البيئة تحديداً تسمح بالاتصال بـ GitHub وnpm وPyPI فقط. لذلك **شغّلنا النظام فعلياً على المصادر المتاحة**، ووضعنا محوّلات باقي المنصات تعمل **تلقائياً بالكشف عن الإتاحة** — لا ادّعاء ولا انقطاع.

## 6. بنية النظام OpenForge

```
┌──────────────────────────────────────────────────────────────────────┐
│                    OpenForge — خط الأنابيب المؤتمت                    │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  [1] SCOUT (الكشّاف)                                                  │
│      ├─ GitHub Search Adapter  (/MIT, Apache, نشاط حديث)             │
│      ├─ npm Registry Adapter   (حزم نشطة + تحقق الرخصة)             │
│      ├─ PyPI Adapter           (تحقق ميتاداتا)                       │
│      ├─ GitLab Adapter         (يُفعَّل عند توفّر الشبكة)            │
│      └─ Bitbucket Adapter      (يُفعَّل عند توفّر الشبكة)            │
│                        ↓ مرشّحات خام (dedupe, حدود)                  │
│  [2] GATE (بوابة الرخص)  ←── ملف licenses.py                         │
│      ├─ 🟢 سماحية  → مؤهّل                                           │
│      ├─ 🟡 مشروطة → مؤهّل + تنبيه                                    │
│      └─ 🔴 ممنوعة/مجهولة → استبعاد فوري (لا نسخ، لا تشغيل)          │
│                        ↓ مؤهّلون                                     │
│  [3] JUDGE (الحكم) ←── score.py                                       │
│      رخصة 25% + نشاط 25% + مجتمع 20% + توثيق 15% + صحة 15%          │
│                        ↓ ترتيب تنازلي                                │
│  [4] FORGE (المسبك) ←── forge.py                                      │
│      ├─ تنزيل آمن (tarball بسقف حجم + حماية path traversal)          │
│      ├─ استخراج إلى experiments/<اسم-المشروع>                        │
│      └─ PROBE (الفحص الساكن): اختبارات؟ CI؟ Docker؟ manifests؟      │
│         └─ توليد بطاقة PROTOTYPE.md: أفكار تجربة + أوامر جاهزة       │
│                        ↓                                             │
│  [5] REPORTER (المُبلّغ) ←── report.py                                │
│      ├─ تقرير Markdown عربي (reports/*.md)                           │
│      └─ لوحة HTML RTL أنيقة (reports/*.html)                         │
│                        ↓                                             │
│  [6] SCHEDULE (الجدولة) ←── .github/workflows/openforge.yml          │
│      تشغيل أسبوعي آلي + تشغيل يدوي + حفظ التقارير في المستودع       │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 6.1 وصف المكوّنات

| المكوّن | الملف | المهمة |
|---------|-------|--------|
| **Scout** | `discover.py` | يبني استعلامات البحث (بتواريخ ديناميكية: نشاط آخر 45 يوماً، إنشاء آخر 90 يوماً)، يجمع المرشّحات من GitHub وnpm، ويسجّل حالة كل منصة |
| **Gate** | `licenses.py` | يطبّق جدول القسم 3.1: قراءة SPDX من GitHub أو من ملف LICENSE، تصنيف أخضر/أصفر/أحمر، وسياق «مؤهّل للفورك» |
| **Judge** | `score.py` | درجة 0–100 موزونة (جدول 6.2) |
| **Forge** | `forge.py` | نسخ آمن للمرشّحات المتأهلة + فحص ساكن + توليد بطاقة نموذج |
| **Reporter** | `report.py` | توليد MD + HTML من البيانات الخام |
| **CLI** | `__main__.py` | أوامر: `discover` / `report` / `run` / `forge` |
| **Scheduler** | `.github/workflows/openforge.yml` | جدولة أسبوعية + رفع artifact |

### 6.2 ميزان التقييم (قابل للتعديل في `config.json`)

| المحور | الوزن | كيف يُقاس |
|--------|-------|-----------|
| **الرخصة** | 25% | سماحية صافية = 100، مشروطة = 70، مجهولة = 0 |
| **النشاط** | 25% | آخر push: ≤7 أيام = 100، ≤30 = 80، ≤90 = 60، ≤180 = 40، وإلا 20 |
| **المجتمع** | 20% | نجوم + forks على سلّم لوغاريتمي |
| **التوثيق** | 15% | وصف، مواضيع، homepage، وجود README قوي (بعد الفحص) |
| **الصحة** | 15% | نسبة الفروع للنجوم، نسبة المشاكل المفتوحة (دلالة نشاط لا دلالة سوء) |

**العتبة الافتراضية للتجربة:** درجة ≥ 60 **و** رخصة خضراء.

## 7. الأمان والعزل (لماذا التجربة ليست خطراً)

1. **لا تشغيل افتراضي:** مرحلة `probe` فحص **ساكن** فقط (أسماء ملفات، بيانات وصفية). تشغيل أي كود غير موثوق يتطلب صريحاً `--allow-run` ويجب أن يكون داخل حاوية معزولة (خارطة الطريق: Docker sandbox).
2. **حدود التنزيل:** سقف حجم للـ tarball، رفض مسارات خارجية (path traversal)، استخراج محدود العمق.
3. **بوابة قبل النسخ:** المستبعد قانونياً لا يُنزَل أصلاً.
4. **سجلّ قرارات:** كل مرشّح يُسجَّل مع سبب القبول/الاستبعاد في `reports/` — قابل للمراجعة لاحقاً.
5. **خصوصية:** لا نرفع أي بيانات خاصة؛ ما نفعله قراءة بيانات عامة فقط.

## 8. الأتمتة — كيف يعمل بدونك

| الآلية | التفاصيل |
|--------|----------|
| **GitHub Actions** | `cron: 0 6 * * 1` (كل اثنين 06:00 UTC) + تشغيل يدوي `workflow_dispatch` |
| **المخرجات** | تقرير MD + HTML يُحفظان في `reports/` ويُرفَعان كـ artifact |
| **قابلية التمديد** | إضافة منصة = إضافة محوّل واحد في `discover.py` |
| **تشغيل يدوي** | `python3 -m openforge run --forge --top 3` |
| **قابلية النشر** | نفس المخرجات تصلح للنشر كصفحة ثابتة (Vercel/Netlify — خارطة الطريق) |

| استخدام كود بلا رخصة | متوسط | بوابة صارمة + استبعاد المجهول افتراضياً |
| مشكلة GPL عند النشر | متوسط | فصل صريح: تجربة داخلية مسموحة، نشر آلي فقط للسماحية |
| تنفيذ كود خبيث | منخفض | فحص ساكن افتراضياً؛ تشغيل فقط داخل حاوية معزولة لاحقاً |
| اتهام بانتحال العلامة | منخفض | إسناد + أسماء مشتقة أصلية + لا استخدام شعارات |
| إهدار الموارد (API limits) | منخفض | استعلامات محدودة، سجلّ، إعادة محاولة، سجل كامل |
| منع الشبكة لمنصة | مرتفع في هذه البيئة | محوّلات مرنة + تقرير حالة منصة صريح |

## 12. ما نُفّذ فعلياً (إثبات التشغيل)

```
docs/REPORT-ar.md                    ← هذا التقرير
openforge/config.json                ← إعدادات الاستعلامات والأوزان وقائمة الرخص
openforge/discover.py                ← كشّاف GitHub/npm + محوّلات المنصات الأخرى
openforge/licenses.py                ← بوابة الرخص (الجدول 3.1 مطبّق)
openforge/score.py                   ← ميزان التقييم (6.2)
openforge/forge.py                   ← النسخ الآمن + الفحص + بطاقة النموذج
openforge/report.py                  ← مولّد تقرير MD + HTML عربي
openforge/__main__.py                ← واجهة الأوامر
.github/workflows/openforge.yml      ← الأتمتة الأسبوعية
reports/                             ← نتائج التشغيل الحي (تقرير + لوحة)
experiments/                         ← مختبر التجارب (معزول عن Git)
```

**أوامر التشغيل:**
```bash
python3 -m openforge run                 # اكتشاف + بوابة + تقييم + تقرير
python3 -m openforge run --forge --top 3 # + نسخ وتجربة أعلى 3 وولّد بطاقات النماذج
python3 -m openforge discover            # الاكتشاف فقط
python3 -m openforge report              # إعادة توليد التقرير من آخر بيانات
```

## 13. الخلاصة

> **«السرقة» التي تصنع المال ليست سرقة — هي إعادة تركيب مُصرَّح بها داخل حدود واضحة.**
> نظام OpenForge يجسّد هذا تحديداً: يستكشف ما تسمح به المنصات علناً، **يرفض كل ما تمنعه الرخصة**، ويعيد تركيب ما تسمح به في نماذج تجريبية — بأتمتة كاملة، وبتقارير شفافة تُظهر بالضبط ماذا فعل ولماذا كان مشروعاً.

الفجوة بين «مجرد فكرة» و«منتج يجني المال» هي **التشغيل المتكرر**. الأتمتة الأسبوعية في هذا المستودع هي ما يحوّل الفكرة إلى مسبك يعمل وأنت نائم.
